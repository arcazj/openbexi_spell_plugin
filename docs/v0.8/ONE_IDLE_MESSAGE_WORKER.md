# One reusable message worker: measured candidate

The `58e6f6c` handoff still fails growth at 78.74 MiB. In its mandatory 45-second window, live Context allocations stay 9.80/9.81 MiB while its retained free allocator memory rises 189.18/220.93 MiB and anonymous memory rises 26.71 MiB. Executor anonymous memory rises 21.56/15.32 MiB; bridge and Listener growth also remain in whole-cgroup acceptance. These observations do not assert absence of leaks.

The earlier eight-worker experiment at `70205ab` is preserved as failed. Its no-swap five-minute comparison grew 583.34 MiB and peaked at 1851.42 MiB. That result is not reclassified or explained away. This candidate uses one lazy reusable worker per rebuilt native process and the current joined/cleared processor cache.

A controlled ASan/UBSan component comparison isolates thread reuse from the existing processor cache. Across all 10,000 callbacks from a fresh component process, including the first worker creation, dedicated-thread heap growth is 85,983,232 bytes versus 524,288 bytes with the single reusable worker. Live allocation counters finish at 78,652/78,684 bytes. No component callback is excluded as warm-up. The earlier warmed diagnostic is also retained in the receipt. Thread IDs use a fixed preallocated array during this measurement, avoiding a growing observer set. The separate sequential case observes 10,000 distinct threads before and one afterward, with the same 10,000 completed callbacks. This is a component result, not mandatory acceptance.

There is no callback queue and no new concurrency ceiling: a busy slot or failed reusable-thread creation falls back to the original dedicated path. Requests always use the original dedicated threads. Twenty-four simultaneously blocked callbacks remain active in the concurrency test. Original admission/RPC/lease deadlines, sanitizers, native resource budgets, original-process identity and the recovery workload are unchanged.

Join waits for the actual callback to return, including after its cancellation flag is set. A joined pooled ticket is reset before the processor can return to the existing bounded instance cache. Idle workers retain no processor, payload, listener or controller proof. The ticket-reset regression covers repeated reuse and alternating listeners; other cases cover 6,000 concurrent callbacks, request isolation, exceptions, cancellation, bounded caches and oversized identities. Eleven component tests pass.

The internal Incoming layout changes, so the complete Context, Executor, shared runtime and private bridge are rebuilt by the normal source-bound build. Whole-native handoff and the installed IDE must be freshly qualified. The durable-audit writer remains inactive until mandatory memory acceptance passes. All eleven full-release gates remain open; no stable publication is performed.
