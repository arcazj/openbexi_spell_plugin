# Native display diagnostic

The GENERIC display candidate passes 35 original native executor cases across
lifecycle, workspaces, routing, reuse, plot timespan, printing and printer
selection. Each family has positive, boundary, failure, recovery and encoding
cases. Recovery reopens the actual persistent driver. Display completion defaults
are exercised without overrides; other cases explicitly choose zero delay.

`conformance/evidence/display.json` checks original TASK protobuf requests,
native Boolean results, persisted effect receipts, independent DSS telemetry,
downloaded PS/ASCII bytes, and the complete installed source map. The retained
overlay changes nine declared Python sources and adds two modules. The original
native binaries remain identical to the qualified fresh-wheel base. Four native
baseline probes retain the old missing API and incorrect behavior.

The report has 35 native leaves and 96 contract/dimension checks for 24 candidate
requirements. Ten acceptance/forgery tests reject changed results, return values,
dimensions, native bytes, undeclared source files, print downloads, patch recipes
and baseline evidence. The backend separately passed 45 real protobuf/HTTP tests.
Historical replay reads the exact captured Git revisions, so later command or
host changes cannot silently substitute new source bytes into this diagnostic.

The initial native run failed on unhandled wrapper/default options and two
incorrect time strings in its probes. Its entire capture remains available at
the path bound in `distribution/evidence/display-focused-review.json`.

The viewer entry point was built into an isolated wheel and installed into a
separate target directory. Its actual console launcher served a copied native
journal, and both PS and VECTOR downloads matched the retained job bytes. The
database hash remained unchanged. The exact wheel, launcher, source modules,
downloads and probe are bound in `distribution/evidence/display-cli-review.json`.
That viewer-only wheel is not a composed runtime release.

No coverage is promoted here. Fresh composed native/Python and driver packages,
the existing language regressions and the final coverage gate remain necessary
before these requirements can be counted toward v0.5. This diagnostic makes no
claim of physical printer output.
